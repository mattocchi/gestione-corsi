# Piano: Tailwind CSS sperimentale per layout e stili custom

Branch: `feature/tabelle-responsive-card`.

## Richiesta

[F-2026-10-17/TAILWIND.1–2] Sullo stesso branch attivare la modalità sperimentale di Vaadin per Tailwind CSS e riscrivere
con Tailwind la parte di layout e di CSS custom.

## Analisi

- Vaadin 25.3 (MCP: *Utility Classes*, *Feature Flags*): Tailwind si abilita con
  `com.vaadin.experimental.tailwindCss=true` in `src/main/resources/vaadin-featureflags.properties`. Le classi vanno
  scritte letteralmente nei sorgenti: il compilatore Tailwind analizza i file e genera solo le utility trovate (niente
  classi composte a runtime). La documentazione avverte che le utility servono poco sui componenti Vaadin (shadow DOM) e
  possono entrare in conflitto con le API di `HorizontalLayout`/`VerticalLayout`.
- Con il flag attivo Vaadin aggiunge a `package.json` `tailwindcss` e `@tailwindcss/vite` 4.3.3 e genera
  `frontend/generated/tailwind.css` con `tailwindcss/theme.css` e `utilities.css` (niente *preflight*, quindi Aura
  non cambia) e `@source '../../..'` sui sorgenti; importa anche `META-INF/resources/styles.css`. Lo sviluppo passa
  da dev bundle precompilato a Vite.
- Verifica nel browser con il flag attivo: Home e login identiche a prima; i fogli globali hanno solo i layer
  `vaadin.base` e `properties` e nessuna regola non stratificata su titoli/paragrafi, quindi le utility (layer
  `utilities`) non sono scavalcate da Aura sugli elementi HTML.
- Tailwind 4: valori arbitrari con variabili `text-(--vaadin-text-color-secondary)`, `[…]` per valori con fallback;
  varianti `dark:` (prefers-color-scheme, come oggi), `after:`, `[&_vaadin-button]:`; breakpoint `sm:` = 640px,
  uguale a `ViewSupport.MOBILE_BREAKPOINT`.
- `styles.css` oggi: ~200 righe; classi usate in 15 file Java, `avviso-sola-lettura` in 14 punti; 2 `getStyle().set`.

### Decisioni

- [F-2026-10-17/TAILWIND.2] Approccio ibrido: le classi custom su elementi e layout diventano utility Tailwind nel Java; in `styles.css` restano solo le regole impossibili o illeggibili con le utility (`::part` della Grid, celle `vaadin-grid-cell-content`), commentate.
- [F-2026-10-17/TAILWIND.2] Combinazioni ripetute come costanti Java in una classe `views/Stili` (es. `Stili.AVVISO`), una sola definizione.
- [F-2026-10-17/TAILWIND.2] Colori, tipografia e raggi dai token Aura con valori arbitrari (aspetto e tema scuro invariati); Tailwind per layout e spaziature.
- [F-2026-10-17/TAILWIND.2] Si convertono anche i 2 `getStyle().set("max-width", …)`; le API di `HorizontalLayout`/`VerticalLayout` restano.
- [F-2026-10-17/TAILWIND.1] Flag attivo in tutti i profili (anche produzione), sullo stesso branch delle tabelle responsive.
