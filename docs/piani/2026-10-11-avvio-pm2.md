# Piano: avvio in produzione con pm2

## Richiesta

Preparare in `deploy/` un esempio per avviare l'applicazione Spring Boot con pm2 in ambiente di produzione, con le variabili d'ambiente necessarie (`ecosystem.config.js` o altra strategia più efficace).

## Analisi

- Oggi `deploy/start.sh` lancia `java -jar gestione-corsi-1.1.0.jar --spring.profiles.active=prod` e il README suggerisce `pm2 start start.sh`: pm2 controlla la shell e non la JVM (segnali di arresto e riavvii meno affidabili), le variabili d'ambiente vanno impostate a mano nella sessione e il nome del JAR cambia a ogni versione.
- `deploy.sh` copia `release/gestione-corsi-1.1.0.jar` sul server come `~/gestionecorsi/gestione-corsi-1.0-SNAPSHOT.jar`: il nome non corrisponde a quello di `start.sh`.
- Configurazione di produzione (`application-prod.properties`, `application.properties`): `DB_URL` (default MySQL locale), `DB_USERNAME` (default `gestione_corsi_user`), `DB_PASSWORD` (obbligatoria), `PORT` (default 8080); il profilo si attiva anche con la variabile `SPRING_PROFILES_ACTIVE=prod`. Java 21.
- Strategia scelta: `ecosystem.config.js` che lancia direttamente `java` (`interpreter: 'none'`), con i segreti in un file `gestione-corsi.env` sul server (fuori da git, permessi 600) letto dall'ecosystem senza dipendenze npm; un `gestione-corsi.env.example` documenta le variabili. Il JAR ha un nome stabile (`gestione-corsi.jar`, configurabile con `APP_JAR`), così un aggiornamento non richiede di modificare la configurazione di pm2.
